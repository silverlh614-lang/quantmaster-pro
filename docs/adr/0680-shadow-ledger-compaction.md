# ADR-0680: Shadow 원장의 중복 저장 제거

@responsibility Stop duplicated Shadow ledger data from growing without dropping observations, outcomes or price history.

- Date: 2026-10-01
- Status: Accepted

## Context

Shadow 스캔은 매분 `paper-experiments.json`과 `paper-strategy.json` 전체를 읽고 다시 쓴다. 운영 규모(기본 관측 약 9,900건, 전략 거래 약 1,200건)로 재현하니 두 원장이 각각 약 200MB였고, 전략 원장 저장 한 번에 약 7초가 걸렸다. 사용자는 계산 지연을 지적하며 무의미한 데이터가 계속 쌓이지 않게 하라고 요청했다.

크기의 대부분은 새 정보가 아닌 복사본이었다.

- 전략 판단마다 근거 실험 ID 전체(수백~수천 개)를 저장했다. 최신 판단, 진입 판단, 청산 판단이 같은 목록을 반복하고, 근거 표본이 늘수록 판단 하나의 크기도 커져 원장이 제곱으로 커진다.
- 기본 관측과 전략 거래마다 그 종목의 최근 약 60거래일 일봉 전체를 복사했다(실험 한 건 크기의 약 74%). 같은 일봉이 날마다 다시 저장됐다.
- 연구 원장은 실험마다 별도 시계열을 만들어 같은 종목의 같은 일봉을 수천 번 보관했고, 빈 시계열도 남겼다.

## Decision

1. ADR-0667 §6의 "근거 실험 ID 고정"을 근거 표본 수와 정렬한 ID 목록의 SHA-256 지문(`experimentIdsDigest`)으로 대체한다. 기준 실험 근거는 추가 전용 기준 원장과 cutoff로 다시 만들 수 있다. 과거 재현 근거는 수와 지문만 남는다.
2. 이 변경 전에 저장된 ID 목록은 첫 저장 직전에 고유 목록별로 `paper-strategy-evidence-archive.json`에 한 번만 옮긴 뒤 지문으로 바꾼다. 이 파일은 스캔 경로에서 읽지 않는다. 보관 파일을 읽을 수 없으면 기존 원장을 덮어쓰지 않는다.
3. 기본 관측과 전략 거래의 진입 일봉은 진입일 기준 최근 21거래일만 남긴다(MA20·20일 수익률 재확인용). 더 오래된 일봉은 마지막으로 기록에 성공한 연구 원장에 같은 종가로 모두 있을 때만 줄인다. 확인 전에는 그대로 둔다.
4. 연구 원장은 같은 출처·종목의 시계열 중 겹치는 날짜의 종가가 모두 같은 것을 하나로 합친다. 종가가 다른 이력(수정주가 재조정 등)이나 겹치지 않는 이력은 따로 남긴다. 빈 시계열은 버린다.
5. 매분 다시 쓰는 두 원장은 들여쓰기 없는 JSON으로 저장한다.

기본 관측 대상·D1/D3/D5 성과·뉴스·수급·조건값·전략 판단 기준·주문 경로는 바꾸지 않는다.

## Consequences

- 전략 판단 한 건은 약 70KB에서 약 1KB로, 실험 한 건은 약 18KB에서 약 6KB로 줄어든다. 기존 기록은 배포 후 첫 연구 갱신과 다음 저장 때 한 번 정리된다.
- 기본 관측은 여전히 하루 약 1,000건(약 6MB)씩 늘어난다. 매분 원장 전체를 다시 쓰는 구조는 남아 있으므로, 이후에도 느려지면 완료된 실험을 매분 쓰는 파일에서 분리하는 작업을 따로 검토한다.
- 진입 기록만으로는 21거래일보다 오래된 일봉을 볼 수 없다. 그 이력은 연구 원장에 종목별로 한 번 보관된다.

## Rollback

- 일봉 정리, 연구 원장 병합, JSON 형식은 이전 코드도 그대로 읽는다.
- 이전 코드는 지문 형식 근거를 읽지 못한다. 되돌릴 때는 `paper-strategy.json`을 보존 위치로 옮기고 전략 원장을 새로 시작한다. 이 변경 전의 ID 목록은 보관 파일에서 복원할 수 있다. 기준 관측과 주문 원장에는 영향이 없다.
