# ADR-0394: P1.5 — 실행 용어 SSOT (외부 노출 라벨 단일 통로)

**Status**: Accepted (P1.5 — 외부 노출 라벨 SSOT, 코드 식별자 일괄 리네이밍은 별도 PR 점진)
**Date**: 2026-05-06

## 배경

ADR-0391/0392/0393 (P0-A/B/P1) 가 ExecutionMode 3-state SSOT 도입했지만 *외부 노출 용어* 가 여전히 legacy 4-state 표현 (`shadow buy` / `shadow trade` / `paper trade` / `simulation` 등) 사용. 사용자 명시 메타 모델 *"방향은 OFF/PAPER/LIVE + shadowLedger always-on, SHADOW 는 학습 layer"* 정합 부재 — 운영자가 텔레그램 메시지에서 `shadow buy` 표현 보면 *실행 모드* 인지 *학습 layer* 인지 모호.

코드 식별자 일괄 리네이밍 (`ServerShadowTrade` / `loadShadowTrades` / `shadowMode` 등 수백~수천 라인) 은 *영속 schema 변경 위험* + *호출자 회귀 위험* 큼. P1.5 는 *외부 노출 layer 만* SSOT 통일 + 코드 식별자는 점진 마이그레이션.

## 결정

### `server/types/executionTerminology.ts` 신규 SSOT

3 export 카테고리:

#### 1. `TERMINOLOGY_MAP` — legacy → modern 매핑 SSOT

| Legacy | Modern | 의미 |
|---|---|---|
| `shadow buy` | `shadowDecisionRecorded` | 학습 영속 단위 |
| `shadow trade` | `shadowDecision` | 학습 단일 결정 |
| `paper trade` | `paperBuyRecorded` | 가상 체결 |
| `live trade` | `liveOrderSent` | 실주문 발사 |
| `shadowMode` | `shadowLedgerEnabled` | 정책 상수 (always-on) |
| `simulation` | `decisionRecord` | 모호한 용어 제거 |

#### 2. `DISPLAY_LABELS` — 텔레그램·UI 한국어 표시 라벨 SSOT

| 키 | 라벨 |
|---|---|
| `shadowDecisionRecorded` | 🌑 학습 기록 |
| `paperBuyRecorded` | 🟡 가상 체결 |
| `liveOrderSent` | 🟢 실주문 발사 |
| `liveBlocked` | 🔴 LIVE 차단 |
| `ghost` | 👻 워치리스트 미연결 |
| `shadowLedgerEnabled` | 학습 ledger (always-on) |
| `decisionRecord` | 결정 기록 |

#### 3. 정책 상수 + 헬퍼

- `SHADOW_LEDGER_ENABLED = true as const` — 정책 SSOT (always-on 의미 격상)
- `modernizeTerm(legacy)` — legacy → modern 변환 헬퍼
- `getDisplayLabel(key)` — 표시 라벨 조회 SSOT
- `detectLegacyTerms(text)` — 정책 가드 (외부 노출 텍스트의 legacy 용어 검출)

### 외부 노출 영역 정합화 (점진)

본 PR 은 SSOT 도입만. 텔레그램 메시지 마이그레이션은 별도 후속 PR (`/exec_matrix` `/mode_consistency` `/gate_audit` 등). 단 P0-A 에서 이미 사용자 명시 신규 용어 (`shadowRecorded` / `paperBuyRecorded` / `liveOrderSent` / `liveBlocked` / `ghost`) 사용 중이라 외부 표시 영역 마이그레이션 부담 ↓.

### 코드 식별자 점진 마이그레이션 (별도 PR)

- `ServerShadowTrade` interface name → 그대로 유지 (영속 schema, 회귀 위험 큼)
- `loadShadowTrades` 함수명 → 그대로 (호출자 50+ 곳)
- `shadowMode` 변수 → 그대로 (분기 로직 정합)

본 PR 의 SSOT 가 *외부 표시 layer 의 변경 시 단일 통로* 역할. 코드 식별자는 분기마다 점진 (P1.5-Code-Rename-N PR 시리즈).

## 안전 invariant

- **외부 노출 layer 만 변경** — 코드 식별자 0줄 변경
- 영속 schema 0 변경 (ServerShadowTrade.mode union 그대로)
- 매수 흐름 wiring 0 (P1-Wiring 별도 PR)
- 호출자 0줄 변경 — SSOT 신규 도입만
- KIS/KRX 자동매매 quota 0 침범
- LIVE 매매 본체 0줄 변경

## 잘못된 해결 방법 영구 차단

1. **본 PR 에 코드 식별자 일괄 리네이밍 통합** — 영속 schema + 호출자 회귀 위험. P1.5-Code-Rename-N 후속 분리 의무.
2. **`shadowMode` 변수 제거** — 분기 로직 SSOT (LIVE vs 학습 모드). 정책 상수 `SHADOW_LEDGER_ENABLED` 와 *별도 의미*.
3. **`SHADOW_LEDGER_ENABLED = false` 옵션 도입** — ADR-0393 always-on 정책 위반.
4. **`detectLegacyTerms` 자동 차단 (lint rule 통합)** — 점진 마이그레이션 의도 위반. 본 PR 에선 *진단 헬퍼만*, 강제 lint 는 후속 PR.
5. **`DISPLAY_LABELS` 한국어 라벨 직접 텔레그램 메시지에 인라인** — SSOT 우회. 모든 호출자 `getDisplayLabel()` 사용 의무 (점진 적용).
