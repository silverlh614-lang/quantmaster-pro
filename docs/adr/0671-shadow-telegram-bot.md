# ADR-0671 — 현재 Shadow 기록을 사용하는 Telegram 봇

상태: Accepted · 2026-09-13

기존 정기 보고는 옛 Shadow 원장·Gate 점수·레짐·Kelly 자료를 섞어 읽고 여러 마감 보고를 중복 발송했다. 새 관측·뉴스/추세 전략·저장 자료 연구와 알림을 일치시킨다.

- `paperBot.ts`가 매분 저장된 `getPaperExperimentView()`만 읽는다. 수집·학습·주문을 실행하지 않는다. 거래일 08:45 준비, 16:10 마감, 일요일 19:00 연구 요약을 개인 DM으로 보낸다. 한국 시간과 KRX 거래일을 사용한다.
- 알림 전용 예약 20개를 제거한다. 데이터 수집·지표 갱신·내부 점검은 유지한다. `scheduledNotificationScope.ts`의 AsyncLocalStorage로 SHADOW의 기존 예약 작업이 만드는 일반 알림만 출력에서 제외한다. 새 봇·수동 응답·실제 주문 영향·TRADE 채널·긴급 알림은 보존한다. 실제 전략에 쓰이지 않는 IPS/Kelly 배율 알림은 SHADOW에서 제외한다.
- `paper-bot.json`은 날짜별 보고 ID, 처리한 가상 매매 이벤트, 전송 시도·Telegram 메시지 ID·결과를 보존한다. 임시 파일 flush 후 rename으로 교체한다. 최초 도입 때 기존 매매를 기준선으로 등록하고 새 진입·청산만 묶어 보낸다. 지연 청산은 평가일 대신 실제 판단 시각으로 탐지한다.
- 메시지 ID가 확인되어야 성공이다. 실패는 1/2/4/8/15분 간격으로 최대 6회 시도한다. 준비 보고 09:30, 마감 20:10, 연구 22:00 이후는 발송하지 않는다. 매매 알림은 생성 후 6시간, 운영 상태는 1시간 뒤 만료한다. 14일 기록을 유지한다. API 수락 뒤 응답 유실이나 저장 전 프로세스 종료까지 정확히 한 번 전송을 보장할 수는 없다.
- 관측 중단·가격 전량 누락·전략 오류·일시정지·복구를 상태 변화 시 통지한다. 시작 직후 10분은 관측 로딩을 기다리며, 확인되지 않은 장애의 복구 알림은 만들지 않는다. 공급 장애를 시장 위험으로 표현하지 않는다.
- SHADOW 메뉴는 `/help`, `/paper`, `/paper_research`, `/paper_bot`, `/control`로 줄인다. 상세 관리 명령은 직접 조회용으로 유지한다. 성과는 비용 반영 독립 실험 평균이며 계좌 수익률로 표시하지 않는다. 과거 재현 표본과 전략 학습 가능 표본을 구분한다.

검증은 외부 통신을 차단한 일정·휴장·재시작·전송 실패·동시 실행·원장 보존·메뉴/명령 테스트와 실제 Telegram 라우팅의 mock 전송으로 수행한다. 실사용 채팅에 테스트 메시지를 보내지 않는다. 복구는 이 커밋을 되돌리며 기존 매매 원장은 변경하지 않는다.
