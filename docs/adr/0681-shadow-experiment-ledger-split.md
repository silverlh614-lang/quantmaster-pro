# ADR-0681: Shadow 관측 원장 분리

@responsibility Keep per-minute Shadow writes small by storing completed experiments in monthly files.

- Date: 2026-10-01
- Status: Accepted

## Context

ADR-0680으로 중복 저장을 없앴지만, 기본 관측은 하루 약 1,000건씩 계속 늘어난다. 스캔은 매분 원장 전체를 읽고 다시 썼고, 엔진 상태 화면도 상태를 만들 때마다 원장 전체를 다시 읽었다. 원장이 커질수록 매분 작업이 길어지는 구조였다.

D5 성과까지 기록된 실험은 더 이상 바뀌지 않는다. 매분 바뀌는 것은 스캔 요약과, 하루 몇 번 바뀌는 진행 중 실험뿐이다.

## Decision

1. 저장 위치를 셋으로 나눈다.
   - `paper-experiments-completed-YYYY-MM.json`: 완료된 실험, 진입일 기준 월별.
   - `paper-experiments.json`: 진행 중인 실험.
   - `paper-experiments-run.json`: 마지막 스캔 요약.
2. 월별 파일은 그 달에 새로 완료됐거나 바뀐 기록이 있을 때만 다시 쓴다. 진행 중 파일은 진행 중인 기록이 바뀔 때만 다시 쓴다. 매분 쓰는 것은 스캔 요약 파일뿐이다.
3. 읽은 파일은 크기와 수정 시각이 바뀌지 않으면 메모리 사본을 다시 쓴다. 성과를 갱신할 것이 없는 기록은 같은 객체를 유지해 바뀐 파일만 고른다.
4. 같은 ID가 진행 중 파일과 월별 파일에 함께 있으면(이동 중 중단) 월별 파일의 완료 기록을 쓴다. 월별 파일의 기록은 지우지 않는다. 읽을 수 없는 파일이 있으면 저장을 멈추고 그 파일을 보존한다.
5. 이 변경 전의 단일 파일은 그대로 읽고, 다음 저장 때 나눈다. 연구 자료 수집도 월별 파일을 함께 읽는다.

관측 대상·성과 계산·전략 판단·주문 경로는 바꾸지 않는다.

## Consequences

- 매분 디스크 쓰기는 스캔 요약 크기로 줄고, 원장 전체 파싱은 파일이 바뀔 때만 한다.
- 대신 파싱한 원장 사본을 메모리에 계속 들고 있다. 이전에는 매분·매 요청마다 같은 크기를 잠깐씩 들었다.
- 장 마감 뒤 성과가 기록될 때와 새 실험이 생길 때는 진행 중 파일과 해당 월 파일을 한 번씩 다시 쓴다.

## Rollback

이전 코드는 `paper-experiments.json`만 읽는다. 되돌리기 전에 월별 파일의 실험을 `paper-experiments.json`에 합친다(같은 ID는 월별 파일 우선). 합치지 않으면 완료된 실험이 화면과 전략 근거에서 빠지지만 월별 파일은 그대로 남는다.
