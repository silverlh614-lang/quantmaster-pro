# ADR-0687: 매일 08:30 학습 기반 추천과 휴장일 연구 발송

@responsibility shadow — scheduled recommendations with frozen evidence

## Status

Accepted

## Context

사용자는 지속적인 지표 학습이 매일 아침 추천주 발송으로 이어져야 한다고 요청했고, 오전 8시 30분 한국 시간과 휴장일 연구 현황 발송을 지정했다. 기존 08:45 해외 뉴스·국내 연관주 보고와 장중 판단 사례는 학습에 따른 추천 명단이 아니었다. 기본 관측의 진입 스냅샷도 당일 첫 장중 자료이므로 다음 날 최신 장전 자료로 재사용할 수 없다.

## Decision

- 기존 매분 Shadow 봇에 매일 08:30 슬롯과 09:00 전까지의 지연 복구 구간을 추가한다. 추천과 휴장일 연구는 CH2에 보낸다. 기존 08:45 해외 뉴스 및 장중·마감 보고는 유지한다. 수동 테스트 발송이나 운영 원장 조작으로 검증하지 않는다.
- `paperMorningRepo.ts`는 기존 정상 스캔에서 같은 회차에 실제 사용한 `PaperSnapshot`, 자율 지표 상태, 보유 종목을 압축 보존한다. 오전 07:00~08:30에 완료된 자료만 발송 원천으로 삼으며 이후 자료가 이를 덮지 않는다. 별도 수집을 시작하지 않으며 저장 실패가 확정 거래를 취소하지 않는다.
- `paperMorningSelection.ts`는 당일·90분 이내·08:30 이전 원천, 자정 학습 경계, 직전 거래일 확정 종가·기술지표와 관측 시각을 확인한다. 장전 확인된 재무·가격 자료를 전일 종가 자료로 소급하지 않는다. 단일 종목의 가격 공급 오류는 해당 종목만 제외한다.
- 기본 추천 수는 최대 3종목이다. 보유 종목을 제외한 동일 종목별 최선의 일치 규칙을 고른다. 검증 연결 규칙을 우선하고 부족하면 등록 후 새 관측이 있는 탐색 규칙을 검증 전 후보로 구분한다. 검증 후보는 규칙의 후반 일당 대조군 차이, 탐색 후보는 학습 차이로 정렬하고 동률은 거래대금·종목 코드로 정한다. 지표 구간·보유기간을 추천 결과에 맞춰 다시 학습하지 않는다.
- `paper-morning-recommendations/YYYY-MM-DD.json`에 추천·근거·원천 시각·순위·원문을 날짜별로 고정한 후 기존 영속 발송 대기열에 넣는다. 재시작·재시도는 같은 원문을 보낸다. 추천 대기 건은 일반 보고보다 우선한다. 성공한 Telegram 메시지 ID와 실제 확인 시각은 별도로 보존한다. 성공한 대기열의 보관 ACK 기록이 실패해도 재발송하지 않고 기록만 복구한다. Telegram 응답 소실 시 정확히 한 번 전송은 보장되지 않는다.
- 휴장, 조건 일치 없음, 자료 미확인을 구별해 모두 정시 보고한다. 생성 시 관측 일시정지이면 새 추천 대신 자료 상태를 기록한다. 이미 생성한 보고는 유효기간 안에서 원문을 재전송한다. 추천은 장전 후보이며 실제 가상 진입은 기존 장중 새 관측 정책으로 판단한다.
- `paperMorningRuntime.ts`는 발송 확인 이후 진입한 거래에 추천 ID를 연결하되 기존 진입 근거를 바꾸지 않는다. 같은 종목이 다른 규칙으로 진입했으면 이를 구분한다. 추천 후 미진입도 조회 결과에 남긴다. `/paper_recommend`와 읽기 전용 `/api/shadow/morning-recommendation?date=YYYY-MM-DD`는 보관 원문과 후속 거래를 조회하고 생성·채널 재발송을 하지 않는다.

## Consequences

학습 결과가 매일 아침 고정 명단으로 제시되고, 이후 가상 매수·미진입·청산·가격 관측과 연결된다. 기준 종가는 참고 가격이며 즉시 체결 가격이나 예상 수익이 아니다. 추천 수를 채우기 위해 자료를 만들거나 기준을 완화하지 않는다. 별도 매도 판단은 향후 확장하며 기존 예약 청산과 실주문 경계는 유지한다.

## Validation and rollback

주말·KRX 휴장일·08:30 경계, 전일 종가·미래 시각·등록 전 관측 배제, 검증/탐색 순위·보유 제외, 영구 원문 복원·충돌 방지, 전송 재시도·우선순위·느린 ACK 시각·ACK만 복구, 발송 전 거래 귀속 금지·다른 규칙 구분·미진입 조회를 테스트한다. 복구 시 새 추천 슬롯과 연결 호출을 중단하되 보관 원문·발송 확인·거래 참조를 읽는 호환성은 유지한다.
